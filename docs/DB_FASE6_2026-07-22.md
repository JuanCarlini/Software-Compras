## Tarea 2 — Función huérfana con search_path mutable (el hallazgo de seguridad real)

La auditoría detectó que `public.update_gu_items_updated_at()` es la **única** función sin
`SET search_path` fijo (corresponde al `WARN function_search_path_mutable` persistente del
advisor). Se sospecha que quedó **huérfana** tras el rediseño CCIP: `gu_items` se recreó con el
trigger `trg_items_updated` que usa `fn_set_updated_at`, y la función vieja + su trigger
`trigger_gu_items_updated_at` habrían quedado muertos.

**Primero investigar (solo lectura):**

```sql
-- ¿Qué triggers (si alguno) referencian la función vieja?
SELECT tgname, tgrelid::regclass AS tabla, tgenabled
FROM pg_trigger
WHERE tgfoid = 'public.update_gu_items_updated_at'::regproc;

-- ¿Qué triggers tiene gu_items hoy? (para confirmar que trg_items_updated/fn_set_updated_at
-- ya cubre el updated_at y el viejo es redundante)
SELECT tgname, pg_get_triggerdef(oid)
FROM pg_trigger
WHERE tgrelid = 'public.gu_items'::regclass AND NOT tgisinternal;
```

**Decidir según el resultado (confirmar con Juan Andrés antes de ejecutar):**

- Si `update_gu_items_updated_at` **no la referencia ningún trigger** → es puro código muerto,
  dropear la función:
  ```sql
  DROP FUNCTION IF EXISTS public.update_gu_items_updated_at();
  ```
- Si todavía existe el trigger viejo `trigger_gu_items_updated_at` en `gu_items` **y es
  redundante** con `trg_items_updated` (ambos setean updated_at) → dropear el trigger viejo y
  luego la función:
  ```sql
  DROP TRIGGER IF EXISTS trigger_gu_items_updated_at ON public.gu_items;
  DROP FUNCTION IF EXISTS public.update_gu_items_updated_at();
  ```
- Si por algún motivo la función **sigue en uso** (algún trigger vivo la necesita) → NO dropear;
  en su lugar recrearla con `SET search_path = ''` (o `public, pg_temp`) para cerrar el WARN,
  igual que las funciones CCIP.

Correr como migración versionada (`apply_migration`) con nombre tipo
`fase6_drop_update_gu_items_updated_at`. Re-correr el advisor de seguridad después: el
`WARN function_search_path_mutable` debe desaparecer.

## Tarea 4 — Confirmar el REVOKE de la función de auditoría (solo lectura)

La auditoría no pudo verificar que `EXECUTE` de `public.fn_audit_log()` (el único
`SECURITY DEFINER`) esté revocado de `anon`/`authenticated`. Si fuera RPC-invocable por anon,
correría como owner (bypass). Verificar:

```sql
SELECT proname, proacl
FROM pg_proc
WHERE proname IN ('fn_audit_log', 'fn_check_avance_100', 'fn_check_imputacion', 'fn_op_gate')
  AND pronamespace = 'public'::regnamespace;
```

`proacl` no debe otorgar EXECUTE a `anon`/`authenticated`/`public` (idealmente `proacl` es NULL
= solo el owner, o un REVOKE explícito). Si alguna tiene EXECUTE para anon:

```sql
REVOKE EXECUTE ON FUNCTION public.fn_audit_log() FROM anon, authenticated, public;
```

(Las funciones de trigger no necesitan EXECUTE para el rol de la app: los triggers corren con
los privilegios del owner de la tabla, no del invocador.)
